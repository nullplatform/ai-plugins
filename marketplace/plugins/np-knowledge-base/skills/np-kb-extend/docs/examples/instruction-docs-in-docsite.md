This organization documents its platform publicly at docs.nullplatform.com (source repo nullplatform/docsite). Every deep analysis must cross the code with that documentation:

1. Find the pages that describe this application's features: run docs_search with the app's domain terms (its name, its main entities, its public endpoints, the CLI commands or UI screens it backs). Try two or three different queries; a single query misses pages.
2. For each relevant page, read it with docs_page and record the mapping as a facet named `documentation`, one entry per page: { path, url, title, describes: [code anchors (file:line) this page documents], sections: [anchors cited] }. This facet is what tells us, when a file changes, which documentation pages must be reviewed. Never copy page text into the catalog: cite `docs:<path>#<anchor>`.
3. Compare what each page claims (endpoints, parameters, defaults, limits, behaviors, error cases) with what the code does. Every difference is a finding of category `doc-drift`, severity medium (high if a documented endpoint or parameter does not exist, or an existing one is undocumented and public), with TWO anchors: the code file:line and the docs:<path>#<anchor>. Undocumented public endpoints are also doc-drift findings.
4. If no page describes this application, record it as a question ("no documentation page found for <app>") — the absence is information.
